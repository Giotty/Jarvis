# Floating research files — JARVIS 0.5.0

This update changes research presentation, not the main Maatouk HUD. It uses existing installed software, selected providers and plugin tools; no paid service, account or new runtime was added. Only Giotty/Jarvis was modified.

1. **Reference inspiration.** Research files use independent rectangular dark-glass panes, thin cyan borders, small title/source strips, compact controls, shadows and offset stacks. Active files brighten and move forward. The supplied floating-pane reference informed these files; it was not copied as an entire interface.

2. **Main HUD separation.** The existing circular reactor, branding, telemetry, provider/perception panels, command area and radial settings remain. Automatic file zones occupy the sides and edges of the core. Manual placement can intentionally overlap it. The wall is not a full-screen research modal.

3. **Narration choreography.** A generic segment contains text, focusObjectId, relatedObjectIds and optional finite actions. Scene keys resolve to validated object IDs. Actual audio completion advances segments, selects another subject or related detail, and computes layout. Files can enlarge, shrink, move to named zones, highlight, park, group or stack. Creation uses validated present_briefing scenes, including progressive append. No sport/product-specific command router was added. Voice disabled or synthesis failure does not falsely simulate finished playback.

4. **Visual roles.** PRIMARY is bright and frontmost; SECONDARY is a related file with a larger context layout where space allows; CONTEXT remains compact/readable at edges; PARKED stays compact until selected. STACKED shows offset headers. USER_LOCKED, PINNED and LIBRARY_SAVED are separate interaction/persistence states. Rich file content has bounded pages; a compact file can be brought forward.

5. **User grab priority.** Pointer hold, drag and resize acquire host tokens with USER_GRABBED, USER_DRAGGING or USER_RESIZING. The held file keeps its geometry and layer despite narration changes. Drag writes only that element's transform at most once per frame, with a final host commit on release. Pointer cancellation, blur, window hiding/closure and renderer failure clean up locks. Stale tokens cannot unlock another gesture.

6. **Deferred transitions.** Incoming visuals stage as visible offset files while any file is held. The latest desired focus and blocked explicit operation replace previous pending requests. Release reconciles the current segment; obsolete narration transitions are not replayed. A moved file becomes user-positioned. New research may append while a file is held; replacing/opening a different workspace requires release.

7. **Pinning/manual placement.** Pinning prevents automatic movement, resizing and stacking. Manually placed files retain their geometry through narration. Explicit user rearrangement is supported, including dragging a pinned file. Agent movement attempts against pinned files return a blocked result. Unpin explicitly before requesting agent rearrangement.

8. **Library/folders.** Save a file, a related group or all files with their positions, sources, topic, groups and image references. The workspace folder selector chooses a save destination. LIBRARY creates folders, searches/moves/renames entries and opens a folder as floating files. Folders are virtual local metadata, with optional parent IDs. Workspace trash only removes the current file. Saved deletion uses existing immutable, expiring, one-use confirmation. Deleted-save badges are cleared while local-file privacy provenance remains. Storage uses validated UUID files under `%APPDATA%/jarvis/Research`; old saved sessions remain compatible.

9. **Automatic modes/images.** The selected model judges generic complexity and usefulness, not keywords: SIMPLE answers/actions, VISUAL_ASSIST one small file, FULL_WORKSPACE multiple aspects/entities, teaching, comparisons or research. Planning runs after an actual public-research decision or a substantial answer; brief conversation/PC commands do not incur a separate classification call. Useful image queries are chosen automatically and run through existing public retrieval. A focused structured presentation request organizes exact source/image IDs through the normal validated tool path. Malformed/unsupported presentations get one organization failure per checkpoint before a source preview, with a final-step reserve and honest incomplete status.

10. **Older files.** All nonclosed files remain in the wall after narration. Context geometry and stacks replace automatic disappearance into a dock. Previous subject/detail files can remain linked through related IDs/groups. End-of-narration leaves the workspace available to inspect, pin, save or trash.

11. **Performance.** Bounded 16 files/40 sources per workspace; 200 saved entries/64 virtual folders; lazy images, bounded fetching/cache, memoized React content, CSS transform/opacity, scoped animation cleanup and reduced/off motion. No extra WebGL library was added. Three-file and 16-file fixtures contained roughly 330–674 DOM nodes and 9–14 MB JS heap across the tested resolutions, with no app scrolling. A short 16-file visible fixture sample had a 7 ms median animation-frame interval; this is a sample, not guaranteed FPS. A separate short Electron-process sample used about 0.48 of one CPU core and 572 MiB summed working sets; shared pages may be counted twice. GPU-engine samples attributed about 11.2% 3D-engine utilization and 57–59 MiB dedicated GPU memory to the fixture's GPU process. These figures include the reactor and Electron, exclude model/voice inference, and are not whole-app performance guarantees.

12. **Verification.** 178 JavaScript regression tests passed, including model-selected modes, automatic images, exact source validation, narration cross-object focus, hold/staging/release, stale tokens, manual/pinned files, selection/group saves, reload/folders/trash, privacy and TTS sanitization. Lint, TypeScript and production build passed. Isolated Electron pointer checks covered holding through five playback-completion callbacks, actual drag/resize, preserved pins, group collapse/expand, real library folder controls, slow/broken images and 3/16-file layouts at 1366×768, 1920×1080 and 2560×1440. Release smoke checks cover the sandboxed bridge, HUD, gestures/folders, save/open/rename and deletion denial/stop/one-use approval. Test data stays in the repository's ignored tmp folder, separate from owner settings/library. No user messages, risky PC actions or other repositories were involved.

13. **Remaining limits.** The installed qwen3.5:9b selected FULL_WORKSPACE and fetched images for the roster request without a visual phrase, producing eight files. The later focused organizer produced valid files in a separate real-model check, but the full live task still encountered invalid organization and source-preview fallback; it took about 149 seconds before retry tightening. Free search results were sometimes about Montreal rather than the requested players, so a correct complete first-line roster and exact player/hometown choreography were not established. Source relevance, model reasoning and latency remain real limits; missing facts must not be invented. The renderer/choreography supports the requested flow, but every future model-generated briefing is not guaranteed. Pseudo-3D is CSS depth, not true 3D reconstruction. Folder opens are bounded and report partial content when limits are reached. Saved images retain public references rather than offline copies; unsaved research is lost on exit. Physical microphone/conversation hardware was not newly verified in this workspace update.

Launch the updated app with `Launch-JARVIS.cmd`, or directly with `release-final/win-unpacked/JARVIS.exe`. Installer: `release-final/JARVIS Setup 0.5.0.exe`. The owner profile remains local/cloud OFF with its selected voice and safety system.
