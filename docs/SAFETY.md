# JARVIS safety model

The model proposes structured tools; the host validates their arguments and assigns fixed risks. Ordinary app launches, browser navigation, scrolling, edit-field focus, verified ordinary typing and actual accessible navigation controls run automatically. Typing focuses a real editable field, verifies the foreground window and reads back the resulting value. It never implicitly submits the field.

Sending/posting/submitting forms, purchases, deletion, installation/uninstallation, privileged settings, shell scripts and sensitive command/payment input require a separate single-action confirmation. Password fields are excluded. Enter-to-submit and ambiguous physical input remain guarded. The model cannot reduce risk or authorize itself. Host-certified automatic clicks use actual observed controls, never a model-supplied safety label.

Approval is immutable, single-use and expires after 60 seconds. Expiry cancels the waiting task so the next request can proceed. Denial stops remaining dependent steps. Global STOP / Ctrl+Shift+Backspace aborts workers and mutes listening. It cannot undo completed changes; moving the mouse to a screen corner triggers PyAutoGUI's fail-safe.

JARVIS temporarily hides its HUD during observation/input and restores it even after failures. Screen targets bind the current window and image region to a single-use proof and recheck before clicking. Accessible controls are refreshed before use. Ordinal selection uses actual peer positions. A visible response to a click verifies the input response, not every downstream semantic result such as a successful login. The assistant must not invent completion.

File access defaults to a selected folder. The owner enabled local-computer access under the current Windows account. Network-share redirects and drive-root mutations are rejected. Reads/searches are bounded; saving, overwriting, moving and recycling files retain approvals. Permanent deletion is unavailable. Filesystem links can change between validation and use. Approved PowerShell scripts remain subject to Windows permissions and UAC; JARVIS does not bypass elevation.

Real mode is the default, with individual capability permissions still required. Simulation is an explicit, visibly marked option. This PC uses real mode with ordinary control permissions enabled. The sandboxed renderer has a finite IPC bridge and cannot access Node or arbitrary shell calls. Source content, screenshots, websites and memories are untrusted data, never authorization.

Research scenes use a bounded typed schema, not model-generated code or HTML. Source/image identifiers must refer to retrieved evidence; chart numbers must occur in cited observations. Image fetches pin validated public DNS addresses, reject private addresses and unsafe redirects, and enforce type/size/time limits. This limits attack surface but does not prove every model-synthesized claim or chart label is correct.

Audio stays local with Whisper and Kokoro/Piper or explicitly selected Windows voices. Background frame watching and analysis always stay local. Foreground screen images may go to the configured cloud provider only when cloud AI and screen-image sharing are enabled and the selected cloud-vision mode permits it. Manual cloud vision applies to explicit UI observation; agent captures require When Needed. Each fresh task screenshot is sent once. Previews remain in memory until exit. Turning off microphone access stops recording; vision off prevents new capture.

Cloud clipboard/file sharing defaults off. Tasks reading restricted contents route to Ollama; generated summaries of such data are marked private and redacted before future cloud requests. External MCP results are treated conservatively as private when either file or clipboard sharing is disallowed. Text intentionally entered by the user, accessible screen text, public research, window titles and selected notes can be context for the chosen provider. The HUD displays CLOUD/LOCAL and reported usage. Cloud OFF forbids cloud inference and model discovery. A per-session cloud request cap is available; it is not a provider billing limit.

Every tool is validated against its schema and current permissions again at execution. Disabled plugins disappear from the model's tool list and cannot execute queued calls. Plugin discovery cannot enable a plugin. Only host-created control proofs can authorize automatic navigation; a model-supplied safety flag is rejected. External MCP tools always require single-action approval, even if the server claims they are read-only. Tool results are untrusted observations and external success claims are not treated as independent verification.

MCP servers are third-party software. Their declared permissions are enforced at JARVIS's tool boundary, not an operating-system sandbox around the server process. Connecting a local server runs its explicitly configured installed executable. Do not connect an untrusted server. Automatic package installation is disabled. Remote MCP uses HTTPS or loopback HTTP; credentials are stored in the encrypted profile and sent only for the configured connection. Account tokens are entered manually; no automatic OAuth flow is currently implemented.

API keys/tokens are stored in `secrets.enc.json` under the local Windows profile and encrypted with DPAPI via Electron safeStorage. There is no plaintext fallback when encryption is unavailable. IPC returns only presence flags. Keys never enter model context or ordinary config, and provider errors are sanitized before logging/display. A custom OpenAI base URL receives the configured key; use only an endpoint you trust. Secret files, environment files and token caches are Git-ignored.

Saved configuration uses atomic writes and a validated backup. A corrupt profile is recovered or reported, never silently replaced with defaults. Task history excludes prompts, arguments and results; incomplete persisted tasks are cancelled on restart. Audit logs omit command, audio, image and clipboard content but may include bounded technical error diagnostics. Explicit memories are unencrypted and protected by Windows account permissions.
