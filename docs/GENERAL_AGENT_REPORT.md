# General agent update

> Historical 0.2.x report. Current UI, providers and launch instructions are in [the 0.3.0 rebuild report](REBUILD_REPORT.md).

0.2.3 follow-up: background research reads public sources, weather uses a direct Open-Meteo tool, and YouTube pages use public metadata and publication-dated channel feeds. Current-information answers without research and unsupported file-access denials receive one bounded correction. Computer-wide filename search has resumable pages across accessible local drives, including hidden/deep directories. File metadata follows the same cloud privacy policy as file contents. Current built-ins expose 64 tools. Read-only manual screen inspection no longer requires a foreground focus change; input actions retain their focus/target checks. See the latest verification section for live checks and limitations.

Only Giotty/Jarvis was modified. Existing HUD, local speech, screen capture, automation, telemetry, memory and installer were retained. Cloud processing remains disabled and no paid requests were made.

1. **Provider architecture:** `core/providers/` exposes a common chat/stream interface, canonical tool calls, capabilities and usage. The rest of the agent does not use provider-specific request formats.
2. **OpenAI:** Responses API support includes conversation, function calls, image input, SSE streaming, structured JSON formats and retained native reasoning items for stateless continuation. `store:false` is used. Mock flows pass; real account access awaits your key.
3. **Claude:** Messages API support includes grouped tool results, vision, streaming text/tool arguments, structured output configuration and preserved native content blocks. Mock flows pass; real account access awaits your key.
4. **Ollama:** Fully local mode remains the default; existing models and voice paths are preserved. Capability discovery uses `/api/show`. Three consecutive real local agent requests completed, including live telemetry and foreground-window readings, without restarting.
5. **Plugin architecture:** Dynamic manifest/schema registry plus actual MCP client support for stdio and Streamable HTTP. Discovery loads more schemas only when needed. Broken/malformed/timed-out calls become structured failures.
6. **Current plugins:** Windows, screen/input, browser, files, research, Steam, Roblox, system, explicit memory and tool discovery. Steam discovers installed libraries and launches known game IDs. No Gmail/Discord/Calendar account integrations are pre-connected.
7. **Permissions:** UI displays each plugin's permissions, tool risks and enablement. Existing screen/mouse/keyboard/browser/filesystem/PowerShell privacy controls remain enforced outside the model. New external plugins start disabled; every external call requires approval. A server's declared permissions do not sandbox its process.
8. **Agent loop:** Both voice and text use `core/agent/agent-loop.cjs`: context → model → validated tools → actual observations → model continuation. No per-phrase desktop action routing. Maximum steps, retries, task/tool/provider deadlines, cancellation and independent read-only parallelism are configurable.
9. **Verification/recovery:** Tool results distinguish success, verified outcome and dispatch. Failed prerequisites prevent dependent batch actions. Non-retryable/consequential actions cannot be blindly repeated. Model answers claiming unverified actions are checked. Approval is frozen, expires and is single-use. STOP and spoken cancel remain available; emergency shortcut is Ctrl+Shift+Backspace.
10. **Screen integration:** Existing window targeting, accessibility IDs, screenshot tools, ordinal matching, visible text and vision are reused. Background frames use local hashes/differences and adaptive sampling. Each fresh agent image is sent once; another observation must be requested to refresh it.
11. **Cloud privacy/usage:** Cloud OFF by default; screen images, clipboard contents and file contents have separate controls. Background screen inference stays local. Restricted file/clipboard tasks switch to Ollama and their generated summaries are kept out of future cloud context. HUD shows provider/model, LOCAL/CLOUD, request counts and reported tokens. Request cap is local to this session, not a dollar billing cap. Prefer Local for Simple Tasks lets Ollama handle the first general inference: direct answers stay local; tool continuations use the configured primary, subject to privacy. It does not classify command phrases.
12. **Testing:** Provider mocks cover text, functions, image formats, native continuation, SSE, malformed/incomplete responses, rate limits, timeouts, cancellation, fallback, capability routing, usage limits and private-data handling. Agent tests cover novel multi-step combinations, schema repairs, parallel reads, serial mutations, approval/denial, restart-free recovery and plugin failures. MCP protocol tests use an actual sandbox stdio server. Python accessibility fixtures and Electron runtime/UI checks are included.
13. **Results:** The full JavaScript suite, Python accessibility suite, lint, TypeScript/frontend build and Windows packaging are checked before handoff. Detailed counts and runtime results are recorded in `VERIFICATION.md`.
14. **Limitations:** Cloud inference has not been tested against a real OpenAI/Claude account. Models must actually support the selected capabilities; use capability overrides for custom model IDs. No unlimited-free hosted API is supplied. Browser/Steam controls still depend on accessible UI and model decisions; no guaranteed action success. Steam play history is not implemented. MCP OAuth, automatic plugin installation, marketplace browsing and OS-level plugin sandboxing are not implemented. Local responses remain slower under high CPU/GPU/RAM load. Physical microphone availability and echo/barge-in require manual testing.
15. **Add a key safely:** Settings → AI Providers → OpenAI or Anthropic → masked API key field → SAVE KEY SECURELY. Keys are DPAPI-encrypted under your local app profile, separate from config, omitted from Git/logs and never returned through IPC. Enter keys in the app, not chat or source files.
16. **Choose provider/model:** Select primary and fallback, enable Cloud AI only if desired, then SAVE CONFIGURATION. SAVE & DISCOVER MODELS queries the configured account/server; you may also enter any model ID. Cloud fallback to Ollama uses the existing local model fields. Privacy → Cloud Vision controls manual/when-needed image sharing. Plugins → review permissions, enable and CONNECT a configured server; save its account token with the encrypted token field if required.
17. **Manual checks:** Launch `Launch-JARVIS.cmd` or `release-final/win-unpacked/JARVIS.exe`. Try an unfamiliar safe multi-step request, live microphone conversation, voice interruption/cancel, browser search/typing, Steam profile selection, screenshot interpretation, enabled/disabled permissions and denied approvals. After entering your own key, test a cloud reply, a tool request and fallback with cloud disabled. Review sensitive confirmations before approving them.
